## Ветки

| Ветка | Зона ответственности |
| --- | --- |
| `team/analytics-qa` | Аналитик. Правила сигналов, контрольные примеры, проверка демо и защита |
| `team/ml-analysis` | ML. Адаптер модели, структура ответа, валидация ссылок на доказательства |
| `team/survey-integration` | Java 1. Две внешние формы, получение ответов и повторная доставка |
| `team/data-backend` | Java 2. Импорт XLSX, история, хранение, аналитические показатели и API |
| `team/dashboard` | Java 3. Обзор, светофор, карточка и связка с API |

`main` — точка сборки рабочего демо. До параллельной разработки согласуйте общий контракт анкеты из ТЗ и формат результата ИИ. Объединяйте небольшие изменения и проверяйте основной сценарий после слияния.

Исходные XLSX и выгрузки храните локально в `data/`. Ключи провайдеров передавайте приложению через переменные окружения.

## Подготовить исторические анкеты

Для запуска с Docker положите две книги в `data/intern.xlsx` и `data/mentor.xlsx`, затем выполните `docker compose up --build`. Откройте [дашборд](http://127.0.0.1:8080). [Запуск без датасета и настройка внешних сервисов](docs/run.md).

```powershell
py -m pip install -r requirements-import.txt
py scripts/import_history.py --intern data/intern.xlsx --mentor data/mentor.xlsx --verify-case
```

Подставьте пути к выданным книгам. Команда проверяет поля, оценки, периоды и повтор строк внутри каждой роли, затем сохраняет `data/history.json`. Это первичная загрузка истории. Автоматический приём из форм подключается к тому же контракту отдельным адаптером.
