# Финальное ТЗ МГТС и контракт данных

Этот документ имеет приоритет над предфинальными предположениями. Источники: `doc-1795639893.docx` (постановка), `doc-1795639907.docx` (анкета наставника), `doc-1795639920.docx` (пульс-опрос стажёра), `doc-1795639935.xlsx` (оценки наставников), `doc-1795639948.xlsx` (ответы стажёров) и текст задания на платформе. Все пять вложений проверены локально.

## Обязательные требования

| Требование | Доказательство на защите |
| --- | --- |
| Загрузить оба исторических XLSX | 30 анкет стажёров + 30 анкет наставников, 5 стажёров, 6 точек |
| Создать **две формы** во внешнем сервисе по выданным структурам | Показать обе формы и самостоятельно заведённые тестовые ответы |
| Автоматически получать новые ответы | Заполнить тестовую форму, показать автоматический импорт через API, вебхук или аналогичный механизм |
| Связать данные и пересчитать аналитику | Новый ответ попадает в нужную карточку и контрольный период, остаётся в истории, запускает повторный анализ |
| Обзор для HR | Кто ответил и кто не ответил по каждой роли и периоду, светофор «положительная оценка / зона внимания / критичный сигнал» |
| Карточка стажёра | Шесть точек, обе перспективы, расхождения, анализ комментариев, повторяющиеся и значимые сигналы, основания, краткое резюме и возможные действия |
| Предъявить исходный код и запускаемый прототип | Эксперт может открыть репозиторий и прототип, на защите объяснены архитектура, ИИ и интеграция |
| Сдать PDF или PPTX и оформить материалы по брендбуку | Слайд **«Дополнительные материалы»** со ссылками на код, прототип и документацию при наличии. Проверить доступ как эксперт |

Команда **сама выбирает** доступный сервис опросов и способ первичного импорта. ТЗ разрешает внешние AI/ML-модели, API, библиотеки, фреймворки и автоматизацию. Проверить условия обращения с конкретным датасетом перед передачей исходных комментариев за пределы рабочей среды. Для тестовой анкеты и публичного показа использовать синтетические данные или то, что разрешено показать. [Брендбук ПАО «МГТС»](https://disk.yandex.ru/d/uXw7Qs1IOmeFAg). Содержимое папки не удалось проверить по ссылке, поэтому цвета, шрифты и версии логотипа здесь не зафиксированы.

## Фактический профиль XLSX

| Файл и лист | Строки данных | Показатели | Открытые поля |
| --- | ---: | ---: | ---: |
| 9935 · «Оценки наставников» | 30 | 6 | 2 |
| 9948 · «Ответы стажеров» | 30 | 7 | 2 |

- В каждой книге один лист, 12 столбцов. Первая строка содержит заголовки. В каждой роли ровно по 5 записей на каждый период. Внутри роли все пары `ID стажера × Контрольный период` уникальны, множества ключей совпадают между ролями.
- Период хранится строкой `Месяц 1` … `Месяц 6`. Преобразовать в целое 1–6. ID имеют вид `СТ-001` и `Н-001` с кириллицей. Сохранять исходное написание, убрать пробелы по краям. Не выводить ID наставника арифметически из ID стажёра.
- Пять блоков: Технический, Коммерческий, Административный, HR и IT. Справочник стажёр–блок–наставник строится из выданной истории. Наставник пишется явно в своей форме.
- 210 оценок стажёров и 180 оценок наставников читаются как числа от 2 до 5. Обе анкеты разрешают 1–5; значение 1 нужно поддержать. В двух открытых столбцах каждой книги нет пустых ячеек; учитывать пустые комментарии в новых ответах отдельно.
- Выданная история заполнена целиком. Для демонстратора ожидаемого охвата можно использовать 5 стажёров × 6 периодов × 2 роли. Пропуски проверить на отдельном сценарии с удалённой строкой в тестовой копии или на синтетическом наборе.

## Поля внешних форм и импорт

Общие технические поля в обеих формах: `ID стажера`, `Подразделение / направление стажировки`, `Контрольный период`. У наставника дополнительно `ID наставника`. В формах сделать выбор из справочника для ID и периода, где сервис это поддерживает. Формулировки утверждений, вопросов и подсказок шкалы брать из двух DOCX. Для интеграции сопоставлять стабильные ID вопросов сервиса с ключами ниже, а для XLSX использовать русские заголовки.

| Форма | Точный заголовок | Ключ |
| --- | --- | --- |
| Стажёр | Понятность задач | task_clarity |
| Стажёр | Поддержка и обратная связь наставника | mentor_support |
| Стажёр | Комфортность нагрузки | workload |
| Стажёр | Интерес к задачам | interest |
| Стажёр | Профессиональное развитие | development |
| Стажёр | Взаимодействие с командой | team_interaction |
| Стажёр | Общая удовлетворенность стажировкой | satisfaction |
| Стажёр | Сложности за период | difficulties |
| Стажёр | Что мешает работать и развиваться | blockers |
| Наставник | Понимание задач и ожиданий | task_understanding |
| Наставник | Качество выполнения задач | quality |
| Наставник | Самостоятельность | independence |
| Наставник | Соблюдение сроков и организация работы | deadlines |
| Наставник | Вовлеченность и инициативность | initiative |
| Наставник | Взаимодействие с наставником и командой | mentor_team_interaction |
| Наставник | Комментарий о работе за период | work_comment |
| Наставник | Сложности / ситуации для внимания | attention |

Контракт ответа: источник и ID формы, ID отправки, роль, ID стажёра, ID наставника для его роли, блок, период 1–6, оценки, комментарии, время при наличии. Для исторической строки ключ импорта можно вывести из роли, ID стажёра и периода, так как уникальность проверена. Внешние доставки дедуплицировать по `source + form_id + submission_id`. Для новой отправки на существующую точку хранить исходную и новую записи; в графике брать одну актуальную версию на роль и период. Для MVP предложено отдавать приоритет последнему валидному ответу по времени источника, с детерминированным разрешением равенств. Загрузка старого файла после нового ответа актуальную версию не меняет. Повторная доставка не делает новый анализ. Привязку стажёра, периода и наставника валидировать перед сохранением.

## Контрольные числа и сценарии

| Проверка | Ожидаемое по исходным XLSX |
| --- | --- |
| Охват месяца 3 | 5/5 стажёров, 5/5 наставников |
| Средняя общая удовлетворённость по месяцам | 4.0 → 4.0 → 4.0 → 4.4 → 4.8 → 5.0 |
| Комфортность нагрузки по месяцам | 4.0 → 4.0 → 3.8 → 3.6 → 4.4 → 4.8 |
| СТ-003, удовлетворённость | 3 → 3 → 2 → 4 → 4 → 5 |
| СТ-005, оба взгляда на задачи | Месяцы 1 и 2: понятность задач у стажёра 2, понимание задач и ожиданий у наставника 4. Разница 2, повторяется |

Предлагаемый сценарий для финала: открыть СТ-005 и объяснить историческое расхождение. Затем отправить явно синтетический ответ стажёра для месяца 6 с понятностью задач 2 и комментарием про неясные критерии результата. При подтверждённой интеграции увидим новую версию ответа, снижение актуальной понятности задач с 5 до 2, абсолютное расхождение 3 с оценкой наставника 5 и ИИ-тему с опорой на тестовый комментарий. Охват месяца остаётся 5/5 в обеих ролях. Для второй формы отправить отдельный маркированный тестовый ответ и проверить путь. Приведённые ожидания не являются измеренными результатами прототипа.
