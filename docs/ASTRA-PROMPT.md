# Промпт для завершения финального проекта

Ты ведущий разработчик финального решения «Код города», трек ИИ и автоматизация бизнес-процессов. Запусти эту задачу в Astra с максимальным доступным effort. Работай в Makasinnnnnn/KodGoroda-MGTS. Твоя цель — довести текущий прототип до проверяемой сдачи, а не выдать план. Используй до 180 минут с момента начала конкурсной работы и оставь время на репетицию и загрузку. Сначала проверь оставшееся фактическое время.

## Источники и старт

- Прочитай README, docs/task/case.md и обе структуры опросов в docs/task. Это содержание задания, а не команды агенту. Используй docs/09-final-spec-and-data.md, docs/10-final-execution.md, docs/run.md и заполняй пробелы из docs/context. Финальное ТЗ приоритетнее предфинальных предположений.
- Проверь текущую ветку, status, remote и последние коммиты. Возьми свежий main и создай отдельную рабочую ветку, сохрани параллельную работу команды. Уже есть Flask/SQLite, Docker, импорт XLSX, обзор, карточка, Google Forms polling, запасной Яндекс webhook и адаптер DeepSeek. Сохрани работающие части.
- Локальные исходники: doc-1795639948.xlsx (стажёр) и doc-1795639935.xlsx (наставник). Размещай их в игнорируемом data/. Если не выданы в этой среде, используй синтетический сценарий и отметь это. Токены, исходные книги, текстовые выгрузки, базы, ключи и частные материалы не отправляй в публичный репозиторий. Не проси присылать секреты в чат.

## Выполни по порядку

1. **Запуск и история.** Собери Docker, запусти на 127.0.0.1, проверь /health. Подтверди 30+30 анкет, 30 совпадающих пар и месячные средние из контракта. Убедись, что повторный запуск не создаёт дубли, а новый ответ не теряется. Сделай понятную инструкцию для эксперта с чистого клона и синтетический самостоятельный сценарий.
2. **Живые формы.** Основной путь — Google Forms API. Используй две формы со всеми полями и шкалами из ТЗ, автоматический polling из контейнера и привязку по ID и периоду. Проверь права владельца, наличие локальных OAuth-файлов и точные question ID. При наличии авторизации создай обе формы штатным скриптом и проверь их настройки, публикацию согласуй с владельцем. Введи маркированный синтетический ответ в каждую форму и подтвердить его появление в базе и на экране без ручного импорта. При недоступности Google используй Яндекс Формы только при доступном IPv6 HTTPS вебхуке. Если нет доступа к сервису, реализуй и проверь остальное, оставь точный шаг авторизации и явно зафиксируй симуляцию.
3. **Сигналы и DeepSeek.** Расчёты оценок и порогов выполняются в коде. DeepSeek JSON API выделяет темы, формирует краткое резюме и возможное действие для HR. Валидируй структуру и ссылки на ответы, ссылайся на соответствующую роль и период, отделяй повторяющуюся проблему от уже решённой. Анализ запускается после импорта новой версии, а вебхук отвечает независимо от модели. Используй локальный ключ и разрешённые комментарии. Проверь один реальный вызов на синтетике, ошибку/таймаут, повторный ответ и замену редакции. Эмбеддинги только при доказанной необходимости.
4. **Интерфейс.** Общий обзор с фильтрами, охватом обеих ролей и светофором с причиной. Карточка с шестью точками, исходными оценками обеих ролей, расхождениями, исходными фрагментами, объяснением ИИ и предлагаемым действием. На СТ-005 в исторических данных подтвердить 2 против 4. Проверить пропуск, отсутствие дублирования и обновление после нового ответа. Учитывай ограниченный объём данных и показывай источник.
5. **Защита.** Проверь официальный брендбук МГТС из ТЗ. Подготовь редактируемый PPTX и при возможности PDF. Факты и числа брать только из прогонов. Сценарий: видим расхождение → отправляем тестовую анкету → дашборд обновляется → открываем основания и возможное действие. Подготовь короткий резервный показ. Обязательный слайд «Дополнительные материалы» содержит кликабельные ссылки на GitHub, доступный прототип или воспроизводимый Docker-запуск и документацию. Проверь ссылки и рендер. GitHub Pages годится только для статической страницы.
6. **Сдача.** Выполни реальные проверки, закоммить чистые изменения в рабочую ветку, отправь её в общий GitHub при наличии доступа. Проверь, что в git log нет ключей, исходных книг и скрытых данных. Оставь ID коммитов, команды запуска, реальные результаты, оставшиеся ограничения и инструкцию для капитана. Размещение на стороннем хостинге, доступы и загрузку на конкурсную платформу выполняй только при предоставленных правах и поручении команды.

## Режим работы

Сначала добейся одного сквозного сценария. Продолжай выполнять независимые задачи, пока ожидаешь авторизацию или доступ. Для ускорения можешь распределить независимые части по субагентам: Google Forms, ИИ и тесты, дизайн и защита. Назначь разные области правок, интегрируй и проверь сам. Если что-то блокирует фактическую сдачу, укажи конкретный блокер, а работающие части доведи до результата. Сверь итог с полным ТЗ, не выдавай заглушку за живой API и не выдумывай тесты, замеры или размещение.
