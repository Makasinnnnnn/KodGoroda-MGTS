# Запуск и интеграции

## Синтетическое демо из чистого клона

Нужны Docker и Docker Compose. Склонируйте ветку с этой инструкцией и выполните команды в корне репозитория. Для демо используйте пустую папку `data/`.

```sh
docker compose build
docker compose run --rm dashboard python -m scripts.seed_demo
```

В корне этого клона создайте `.env` со строкой `MGTS_WEBHOOK_TOKEN=local-demo-token`. Это значение предназначено для синтетического показа на loopback. Запустите:

```sh
docker compose up -d --wait
curl -fsS http://127.0.0.1:8080/health
```

1. Откройте [обзор за месяц 6](http://127.0.0.1:8080/?month=6) и [карточку DEMO-2](http://127.0.0.1:8080/interns/DEMO-2?month=6). В обзоре 59 версий, охват 5/5 стажёров и 4/5 наставников. В карточке 2 у стажёра и 4 у наставника.
2. Выполните `docker compose exec -T dashboard python -m scripts.replay_demo`. Команда отправляет два маркированных ответа через локальный обработчик вебхука. Для каждой роли будет `202 accepted`.
3. Нажмите «Обновить». Теперь 61 версия, охват 5/5 по обеим ролям, а у DEMO-2 в месяце 6 оценка 1, расхождение +3 и новый комментарий в исходных ответах.
4. Повторите команду. Для обеих ролей будет `200 duplicate`. После `docker compose restart dashboard` история и 61 версия остаются в SQLite.

В этом сценарии интерфейс указывает синтетический источник, а DeepSeek по умолчанию отключён. Для повторной репетиции с нуля используйте новый клон с пустой папкой `data/`.

## Организаторская история

В отдельном клоне поместите `doc-1795639948.xlsx` как `data/intern.xlsx`, а `doc-1795639935.xlsx` как `data/mentor.xlsx`. Проверьте 30 + 30 ответов, 30 пар, средние и контрпримеры. Команда создаст локальный `data/history.json` только после успешной проверки.

```sh
docker compose build
docker compose run --rm dashboard python -m scripts.import_history --intern data/intern.xlsx --mentor data/mentor.xlsx --verify-case
docker compose up -d --wait
```

При старте приложение использует `data/history.json`, если файл существует, или читает обе книги XLSX напрямую. Повторный старт сохраняет актуальные версии ответов из опросов. Вся история и результаты разбора хранятся в `data/dashboard.sqlite`.

Для запуска без Docker установите Python 3.10 или новее, затем выполните `python -m pip install -r requirements.txt` и `python app.py`. В Windows можно использовать `py` вместо `python`. Compose читает `.env` автоматически. Для прямого запуска задайте переменные окружения в терминале.

## Google Forms

API бесплатен и подходит для запуска на компьютере жюри. Контейнер периодически сам читает ответы, входящий публичный порт не нужен. Google-авторизацию выполняет владелец форм на своём компьютере.

1. В Google Cloud Console создать проект, включить Google Forms API, настроить экран OAuth. Для тестового приложения добавить владельца форм в тестовые пользователи. Создать OAuth Client ID типа **Desktop app** и сохранить его JSON в `data/google-client.json`.
2. Подготовьте локальную историю из двух XLSX или выполните `python -m scripts.seed_demo` для демонстрационного справочника. На компьютере с браузером установите зависимости и выполните `python -m scripts.setup_google_forms`. Войдите как владелец. Скрипт создаст две закрытые формы, сверит шкалы и привязку вопросов, сохранит ID в `data/google-forms.json` и токен в `data/google-token.json`. При повторном запуске скрипт проверяет существующие формы.
3. Владелец проверяет настройки доступа респондентов и публикует формы через интерфейс или запускает скрипт с `--publish`. Скрипт печатает ссылки респондентов.
4. Перезапустите контейнер, отправьте по синтетическому ответу через обе формы и обновите дашборд после опроса API. На обзоре виден статус синхронизации. Интервал по умолчанию 15 секунд.
5. Для рабочего режима используйте стабильную OAuth-настройку и подтверждённые права владельца. Тестовые OAuth refresh-токены внешнего приложения Google обычно истекают через 7 дней. Для жюри, которому нельзя передавать токен владельца, достаточно локального прогона истории. Живую интеграцию покажите с машины команды или используйте отдельный демонстрационный аккаунт.

Новые отправки привязываются к стажёру, роли и периоду. Google response ID и timestamp редакции отличают новую редакцию от повторной доставки. Если форма недоступна, ранее полученные анкеты остаются в SQLite. При настройке будьте готовы проверить доступ Google Forms и API на используемой сети.

[Квоты и стоимость Google Forms API](https://developers.google.com/workspace/forms/api/limits) · [Чтение ответов](https://developers.google.com/workspace/forms/api/reference/rest/v1/forms.responses/list) · [Публикация форм](https://developers.google.com/workspace/forms/api/guides/publish-form)

## DeepSeek

Скопируйте `.env.example` в `.env`, задайте `DEEPSEEK_API_KEY`. Включайте `DEEPSEEK_SEND_COMMENTS=1` только после подтверждения, что этот текст разрешено отправлять в DeepSeek. Синтетический набор позволяет отдельно проверить вызов. В модель уходят роль, месяц, текст и идентификатор фрагмента. Имена и ID стажёров не передаются как отдельные поля. Свободный текст может содержать личные данные.

Модель по умолчанию `deepseek-flash`. Приложение проверяет структуру JSON и принадлежность ссылок текущей карточке, показывает исходный фрагмент, роль и месяц. Новая актуальная версия анкеты запускает фоновый разбор. При таймауте оценки доступны, а карточка показывает состояние ошибки. Перезапуск повторяет незавершённые и ошибочные задачи. [Документация DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)

## Правила светофора

- Красный: оценка ≤2 при падении ≥2 по тому же показателю или при разнице ≥2 в сопоставимой паре оценок задач.
- Жёлтый: низкая оценка, падение хотя бы на 1, разница по задачам от 2 или повтор проблемы в комментариях как минимум в двух разных месяцах.
- Зелёный: обе роли ответили, причин для внимания нет. Серый: пары ответов нет и сработавших сигналов нет. Факт пропуска виден отдельно при любом цвете.

Падение считается от предыдущего доступного ответа той же роли. Знак разницы показывает оценку наставника минус оценку стажёра. Любое явно описанное решение закрывает подтверждённую проблему, если в том же месяце нет замечания о её сохранении. Одновременные оценки по несопоставимым вопросам выводятся отдельно.

## Автоматические проверки

```sh
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

Тесты подставляют ответы Google Forms и DeepSeek на границе API. Учётные данные для этих прогонов не нужны. Для проверки живых сервисов используйте инструкции выше.

## Яндекс Формы как запасной вариант

Два ролевых маршрута `POST /webhooks/yandex/intern` и `POST /webhooks/yandex/mentor` принимают JSON. Добавить заголовок `X-Webhook-Token` со значением из `.env`. В теле передать `form_id`, `submission_id`, `intern_id`, `period`, `department`, `mentor_id` для наставника и поля из контракта ТЗ. Поля оценок и комментариев можно передавать прямо в объекте либо в объектах `scores` и `comments`. Переменные ответов экранировать JSON-фильтром. Нужен внешний HTTPS-адрес с IPv6, проксировать только вебхуки и сохранять дашборд закрытым. [Справка Яндекс Форм](https://yandex.ru/support/forms/ru/send-request)
