# Решение по ИИ для трёхчасового MVP

Основной вариант — доступный генеративный API со структурированным ответом по JSON Schema. Семантический поиск и векторное хранилище для первых 60 анкет не нужны. Есть точный ключ стажёр × месяц, и для сводки достаточно нескольких выбранных запросом комментариев. Для поиска похожих формулировок между потоками можно позже добавить эмбеддинги с отдельной оценкой качества.

## Схема работы

1. Backend рассчитывает тренды и расхождения по оценкам. Выбирает комментарии из текущего и нескольких предыдущих периодов того же стажёра.
2. Адаптер передаёт выбранный контекст модели. Вход содержит ID записи, роль, месяц и текст. При использовании внешнего провайдера сначала подтвердить допустимость передачи конкретных данных.
3. Модель возвращает `themes[]`, `summary`, `suggested_actions[]`, `evidence_ids[]` и `insufficient_data`. Для каждой темы хранить собственные ссылки на исходные ответы. Комментарии обрабатывать как данные. Самостоятельных действий модели в системе нет.
4. Сервер проверяет JSON, допустимые поля и принадлежность ссылок данной карточке. Тему считать повторяющейся при подтверждении минимум в двух периодах. Неподтверждённые причины в вывод не включать. Числовые сигналы остаются видимыми при таймауте или сбое ИИ.
5. Анализ запускать после фиксации новой версии анкеты, желательно отдельно от HTTP-ответа импорта. Ключ кэша: стажёр, версия затронутой истории, провайдер, модель и версия промпта. В UI различать «ожидает анализа», «готово» и «ошибка».

## Локальный вариант

Оставляем тот же контракт и меняем адаптер. Если внешняя передача запрещена, API недоступен или компьютер уже уверенно запускает подходящую локальную модель, использовать локальный inference через Ollama. Квантование выбирать по фактической памяти, скорости и качеству русского языка. Проверить до выбора на нескольких синтетических комментариях. Замерить холодный и повторный запуск, целостность JSON и качество привязки к источникам. На финале ограничиться одним реально работающим провайдером.

Примеры возможностей API: [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) и [Ollama Structured Outputs](https://docs.ollama.com/capabilities/structured-outputs). Конкретный поставщик, модель и способ вызова пока не выбраны.

## Что требуется уточнить

1. Какой сервис опросов уже доступен команде и может отдавать ответы автоматически? Кто заведёт две формы и проверит первый тестовый ответ?
2. Какой LLM API и ключ уже есть у команды? Можно ли передавать ему подготовленные комментарии из выданных файлов? Если нужен локальный запуск, на каком ноутбуке есть установленная модель и сколько доступно RAM/VRAM? Значения ключей сюда и в Git не присылать.
3. Где экспертам показываем прототип и исходный код? Для подключения remote нужен адрес общего репозитория или владелец, имя и правила видимости нового. Для прототипа нужен доступный хост либо подтверждение, что допустим локальный запуск по инструкции.
