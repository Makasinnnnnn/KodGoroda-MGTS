# Рабочий протокол на 180 минут

## До старта

Распределить роли, проверить ноутбуки, зарядки, общий канал обмена файлами, доступ к среде разработки и возможность открыть презентацию локально. Подготовить пустой репозиторий или способ быстро создать его на месте, если это допустимо по регламенту. Приоритет у инструмента, которым владеет команда и который запускается в окружении за несколько минут.

## Назначение ролей

| Ответственный | Первый результат | Результат для защиты |
| --- | --- | --- |
| Аналитик и координатор | Матрица требований, один сценарий HR, ответы наставника и критерии приемки | Питч, измерения, список ограничений и сверка комплекта сдачи |
| ML | Допустимая модель ответила на один безопасный пример, проверен формат ответа | Тема и сводка со ссылками на ответы, 5–10 разобранных кейсов и явный режим ошибки |
| Java 1 | Источник опросов прислал или вернул один ответ | Повторяемая синхронизация, защита от дублей, видимый статус загрузки |
| Java 2 | Сохраненный ответ доступен по согласованному контракту | Расчет динамики, хранение, устойчивый запуск и итоговый комплект |
| Java 3 | Экран показывает один реальный объект из контракта | Общая картина, карточка, понятные состояния загрузки и пропуска |

Каждый владеет своей частью до первого сквозного прогона. После этого работа идет по списку проблем демо. Один интегратор принимает изменения в основной ветке. В 0, 45, 100 и 150 минут провести короткую общую сверку.

## Временные ворота

| Минуты | Действия | Условие перехода |
| --- | --- | --- |
| 0–15 | Прочитать ТЗ, проверить данные, модель и сервис анкетирования, выяснить формат сдачи | У каждого обязательного требования есть владелец и способ проверки |
| 15–25 | Определить идентификаторы, один вопрос сравнения, договориться о формате данных и экранах | Все части работают с одним минимальным примером |
| 25–65 | Параллельно интеграция, хранение и расчеты, ИИ, интерфейс, каркас презентации | Каждый блок выдает проверяемый результат |
| 65–105 | Соединить блоки и прогнать один сценарий от анкеты до карточки | Данные приходят и обновляют интерфейс без правки вручную |
| 105–135 | Исправить блокеры, измерить сценарии, проверить ошибки и повторный импорт | Есть работающий вариант и факты для защиты |
| 135–155 | Прогнать демо, взять резервные снимки или запись, завершить слайды | Демонстрация воспроизводится, ограничения названы |
| 155–180 | Собрать комплект, перепроверить с чистого запуска и репетировать | Есть проверенные файлы, ссылки и резервное демо |

Загрузка отдельно в окно 13:15–13:25 МСК по памятке, если наставник не назовет другой срок. Капитан подтверждает сдачу в личном кабинете.

При упоре на 45-й минуте: владелец блокера формулирует конкретный вопрос наставнику, описывает пройденную проверку и предлагает допустимый путь. Если данные пришли без ключа сопоставления, покажите стороны по отдельности и уточните, есть ли таблица связей. Если модели нельзя передавать исходные комментарии, уточните локальное исполнение или обезличивание. Если сервис опросов не доступен, выданный датасет поддерживает проверку аналитики, а статус интеграции в демо отражает фактическое состояние.

## Вопросы наставнику в первые 10 минут

1. Где полное ТЗ, датасет, словарь полей и порядок загрузки результата? Какой лимит на защиту?
2. Какой сервис анкетирования обязателен и как получить тестовую форму, доступ к API или webhook? Какие разрешены альтернативы?
3. Есть ли устойчивый идентификатор стажера у обеих сторон, календарь ожидаемых ответов и сопоставление вопросов?
4. Какие сигналы, показатели, пороги и отображение считаются обязательными? Есть ли данные для ручной проверки?
5. Разрешено ли отправлять комментарии в конкретную внешнюю модель? Есть ли локальная или выданная модель? Данные можно сохранять и показывать на слайдах?
6. Нужно ли обработать весь датасет, какие артефакты загрузить, нужно ли развернуть проект, допускаются ли заготовки?

## Контракт данных, уточнить по схеме

- Ответ хранить с устойчивым ключом источника, временем и версией. Однозначно различать автора и стажера, к которому относится ответ.
- Период надежнее привязать к номеру месяца программы или явному диапазону анкеты. Дату отправки использовать как дату отправки.
- Минимум для одного ответа: `source`, `response_id`, `intern_id`, `role`, `period`, `submitted_at`, `question_id`, `scale_id`, `score` или `comment`. Названия условные.
- Один и тот же ответ при повторном импорте обновляется или игнорируется по правилам сервиса. Измененный текст переанализируется, если версия изменилась. У агрегата нет дублей после двух запусков.
- Неизвестные участники или шкалы остаются в отдельном списке проблем данных. Не соединять по одному имени и не превращать отсутствующую оценку в ноль.
- Для графика различать сопоставимый вопрос, роль и период. Показывать объем сравнения и пропуски. Процент ответивших требует ожидаемый знаменатель, иначе показывать количество полученных ответов.

## Два экрана

**Обзор.** Количество ответов обеих сторон, динамика сопоставимой метрики за доступные месяцы, несколько сигналов с объяснением, фильтр по периоду. Клик по сигналу открывает карточку.

**Карточка.** История по месяцам, различимые серии стажера и наставника, комментарии и темы, исходный вопрос и фрагмент ответа, время обновления. Подсветка предлагает куратору проверить ситуацию. Решение принимает человек.

## Как отделить сигнал и ИИ

- Правила считают разницу между сопоставимыми оценками и падение относительно предыдущего доступного периода. Для пропуска проверяют, должен ли был прийти ответ. Значения порогов фиксировать как параметры и объяснять на защите.
- ИИ возвращает тему, нейтральное краткое описание и ID ответов. Уточнения или предположения помечаются. Если подтверждающий ответ отсутствует, UI показывает статус «недостаточно данных».
- Текст анкеты передавать модели как данные. Комментарии с инструкциями не должны менять формат ответа, инициировать действия или раскрывать сведения. Ограничить JSON полями, проверять ID на принадлежность текущему стажеру, рендерить комментарии как текст.
- При запрете облака не отправлять данные на внешние сервисы. Использовать только разрешенный путь. При недоступности ИИ показывать измеримый результат расчетов отдельно и указать ограничение на защите.

## Минимальная приемка

| Сценарий | Что должно случиться |
| --- | --- |
| Стабильные оценки | График точен, предупреждение не появляется |
| Ухудшение | Сигнал с предыдущим и текущим значением, правильный период и сторона |
| Расхождение оценок | Сравнивается согласованный показатель, видно обе стороны |
| Одна сторона не ответила | Видно отсутствие ответа, среднее и сравнение не подменяются нулем |
| Повтор импорта и исправленный ответ | Нет дублей, изменение применено по контракту |
| Неоднозначный комментарий | Тема связана с исходником, система не изобретает причину |
| Сбой API или модели | Понятный статус, уже загруженные данные и расчеты доступны |

Данные для демонстрации помечать как выданные организаторами либо синтетические. Замерять реальные результаты. Сэкономленное время = время ручной проверки минус время с дашбордом на одинаковом наборе. Если замера нет, показать дизайн эксперимента как план проверки.
